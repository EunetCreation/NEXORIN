# APP67J · Obstacle-Aware Smart Routing

## Purpose

APP67J replaces simple elbow routing with one deterministic routing contract for the SLD editor and controlled SVG/PDF output. The router keeps engineering terminals fixed, produces orthogonal paths, avoids equipment and reserved A3 regions, reduces crossings, and preserves routes explicitly marked as manual.

## Routing authority

| Context | Authority |
|---|---|
| Interactive editor | `resources/js/sld-smart-router.js` |
| Controlled SVG and PDF | `app/Services/Sld/SldSmartRouter.php` |
| Symbol terminals | APP67H canonical symbol and port registry |
| Network validity | APP67I electrical-rule registry |
| Saved drawing schema | `nexorin-sld-v1.5.0`, editor version 15 |

Both router implementations use the same version identifier: `67J.1`.

## Routing priorities

The visibility-grid A* router evaluates candidate paths in this order:

1. Keep source and destination port coordinates exact.
2. Keep every segment horizontal or vertical.
3. Do not enter expanded equipment or keepout rectangles.
4. Avoid existing wire crossings when a valid detour exists.
5. Maintain parallel spacing between nearby wires.
6. Minimize bends.
7. Minimize total Manhattan length.
8. Prefer network lanes for DC, AC, neutral, PE, communication, control, and measurement paths.
9. Produce deterministic output for the same graph state.
10. Use a visible perimeter fallback and report a conflict when no valid corridor exists.

A shared terminal at the true source or destination is not counted as a crossing. An unmodelled T-intersection inside a route remains a crossing.

## Clearance profiles

| Profile | Equipment clearance | Parallel channel spacing | Intended use |
|---|---:|---:|---|
| Compact | 12 units | 9 units | Dense internal diagrams |
| Standard | 18 units | 12 units | Default engineering drawing |
| Generous | 26 units | 16 units | Presentation and review drawings |

The selected profile is stored per wire as `routing_clearance`.

## Automatic and manual routing

### Automatic

`routing_mode: auto` allows the editor to rebuild the route when:

- a wire is created;
- connected equipment moves or changes size;
- a new obstacle enters the route;
- a stale route is loaded;
- **Route all** is executed;
- the clearance profile changes;
- SVG or PDF detects a missing, blocked, stale, or old-version route.

### Manual

`routing_mode: manual` preserves the saved control points when surrounding equipment moves. Manual mode remains subject to APP67I electrical validation. It does not silently switch back to automatic routing.

## Obstacles

The editor treats the following as route obstacles:

- electrical equipment nodes;
- annotations;
- explicit shapes marked `routing_keepout: true`.

The A3 renderer also reserves:

- sheet header;
- engineering notes;
- symbol legend;
- title block.

Source and destination equipment are excluded from obstacle blocking for their own wire. Their port lead segments remain fixed to the canonical terminal anchors.

## Crossing and spacing control

Existing wires are converted to orthogonal segments before the next wire is routed. Candidate routes receive:

- a strong penalty for perpendicular crossings;
- a proximity penalty for parallel segments closer than the selected channel spacing;
- a higher proximity penalty between different network classes.

Network lane offsets provide a stable ordering preference. They do not override obstacle safety.

## Editor interface

### Manage ribbon

**Route all** rebuilds every automatic wire. Its badge reports:

- `CLEAR`;
- number of crossings;
- number of clearance conflicts.

### Wire Inspector

Each manual wire exposes:

- routing mode;
- clearance profile;
- strategy;
- path length;
- bend count;
- crossing count;
- clearance-conflict count;
- **Rebuild smart route**;
- source and destination selection.

### Root health contract

The editor root publishes:

- `data-routing-status`;
- `data-routing-crossings`;
- `data-routing-conflicts`.

These attributes support inspection mode and Playwright regression tests.

## Saved data contract

Automatic and manual connections can store:

```json
{
  "routing_mode": "auto",
  "routing_clearance": "standard",
  "router_version": "67J.1",
  "route_strategy": "visibility-grid-a-star",
  "route_length": 540,
  "route_bends": 4,
  "route_crossings": 0,
  "route_clearance_conflicts": 0
}
```

The editor-level routing summary stores total wires, length, bends, crossings, and conflicts.

## SVG and PDF contract

Controlled SVG uses the PHP router when a route is:

- absent;
- generated by an older router version;
- stale relative to current terminal positions;
- blocked by equipment or an A3 reserved region.

Each exported wire group carries:

- `data-router`;
- `data-route-strategy`;
- `data-route-crossings`;
- `data-route-clearance-conflicts`.

PDF inherits the same SVG geometry. It does not run a separate visual routing algorithm.

## Scope boundary

APP67J handles geometry and route health. It does not calculate cable ampacity, protection coordination, voltage drop, inverter sizing, or bill-of-material changes. Those engineering-controller functions belong to APP67K and continue to use APP67H and APP67I as their technical foundation.
